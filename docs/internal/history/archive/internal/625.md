## Summary

v1.1.6 ships three major feature areas: External Worker Enhancements (EWE),
DarkIRC multi-tenant hardening, and v8 ports schema. Overall quality is
solid — the security improvements (SecretString, constant-time auth,
body-size cap, fail-closed adapter URL) are well done and the integration
test coverage for the external worker path is genuinely good.

No critical crash bugs found. Several moderate issues and a handful of
low-severity concerns. The release notes are honest about known issues.

**Caveat:** No `cargo test` or `cargo clippy` was run — the Umbrel
container lacks g++. All findings are from static analysis. Full crate
compilation + test run should happen on a remote host before any
production deploy.

## Findings

### MOD-1: Double-counted lease in `execute_task` wait=true path
**File:** `ic/src/orchestrator/external_worker.rs`, lines 262 + 293-364
**Severity:** Moderate (load-balancing accuracy, not correctness)

`execute_task` acquires an initial `lease` at line 262 (via `lb.acquire()`)
to derive `url`/`auth_token`/`pool_key`. This lease lives for the entire
function scope.

In the `wait=true` path (line 293+), the retry loop acquires FRESH leases
(`attempt_lease`) at lines 304-310 for each attempt. The original `lease`
from line 262 is never used for actual task execution in this path — it's
dead weight that holds an active-connection count on one endpoint for the
entire retry loop duration.

**Impact:** For `LeastConnections`, the initial lease inflates one
endpoint's count by 1 while a task runs on a different endpoint. Concurrent
LeastConnections decisions on other tasks see a skewed active count. Not a
correctness bug (failover still works), but the load balancer is less
accurate when `wait=true`.

The `!wait` path is correct — the initial `lease` is moved into the spawned
task (line 377: `let _lease = lease;`).

**Fix:** In the `wait=true` branch, `drop(lease)` before entering the retry
loop (after extracting url/token/key if still needed, or just re-derive
them from the first `attempt_lease`).

### MOD-2: RoundRobin `acquire_excluding` doesn't actually exclude
**File:** `ic/src/orchestrator/external_worker.rs`, lines 589-591
**Severity:** Low-Moderate (works by accident, but misleading API)

`acquire_excluding` for RoundRobin just does `fetch_add(1) % len` — the
`excluded_urls` parameter is ignored entirely. The circuit-breaker
failover for RoundRobin works by accident: round-robin's natural index
advancement moves to the next endpoint on retry, so it happens to skip the
just-failed one (usually).

Edge case: with exactly 2 endpoints [A, B], if A fails on the initial
lease (index picks A), the retry picks B (different index) — works. But
with concurrent tasks bumping the shared `current_index`, the retry could
theoretically land back on A if another task consumed an index slot in
between. Unlikely but possible.

The LeastConnections `acquire_excluding` correctly filters by URL.

**Recommendation:** Add explicit exclusion to the RoundRobin branch too
(skip excluded indices in the cycle). Low urgency since it mostly works.

### LOW-1: `is_loopback` treats `0.0.0.0` as loopback
**File:** `ic/src/orchestrator/external_worker.rs`, line 118
**Severity:** Low (false negative on cleartext warning)

`0.0.0.0` is "any address", not loopback. Including it in `is_loopback`
means `ws://0.0.0.0:9090/...` won't trigger the cleartext-credentials
warning, even though binding to 0.0.0.0 means the worker is reachable on
ALL interfaces (including external). If someone configures a worker with
`ws://0.0.0.0`, credentials would be sent cleartext on the network with
no warning.

In practice, workers are configured with `127.0.0.1` or specific IPs, so
this is unlikely to bite. But `0.0.0.0` should probably NOT be in the
loopback set.

### LOW-2: mt-admin inline `ports_migrate_v8()` lacks collision check + backup
**File:** `ic/scripts/lunarwing-mt-admin.sh`, `ports_migrate_v8()` function
**Severity:** Low (rename-only migration, low collision risk)

The standalone `migrate-ports-v8.sh` has:
1. A backup (`cp -p` before migrating)
2. A post-migration collision check (`group_by` on all ports, abort if any
   collision)

The inline `ports_migrate_v8()` in mt-admin has neither. Since v8 is a
pure rename (reserved_3 → nanocode_health, reserved_4 → pebble_health),
the risk is very low. But if the inline migration runs on a corrupted
registry, there's no safety net.

The standalone script is the "explicit, safe" version; the inline is the
"auto-run on every mt-admin invocation" version. The asymmetry is
understandable but worth noting.

### LOW-3: `configure_nanocode` doesn't preserve original file permissions
**File:** `ic/scripts/lunarwing-mt-admin.sh`, `configure_nanocode()` function
**Severity:** Low

`configure_nanocode` writes via `cat "$tmp" > "$env_path"` then `chmod 600`.
This hardcodes 600 even if the original file was 640 or 644. If any process
reads `lunarwing.env` as a group member, it would lose access. Not a
security issue (600 is MORE restrictive), but could cause unexpected
failures in tooling that reads env as a different user.

### LOW-4: Commit hygiene — vague messages
**Severity:** Process (not code quality)

Multiple commits in this release have extremely vague messages:
- `d`, `ud`, `s`, `ic10`, `4`, `4done`, `draft`, `eww`, `pause4compile`

This makes `git blame` and `git log` archaeology difficult. No code
quality impact, but hurts maintainability. Consider squashing or enforcing
conventional commit messages.

### INFO-1: DarkIRC adapter `pending_ack` semantics — correct
**File:** `darkirc_adapter.py`

The at-least-once delivery implementation is correct:
- `/poll` serves `pending_ack + message_queue`, moves all to `pending_ack`
- `/ack` clears `pending_ack`
- If host crashes before ack, next `/poll` re-serves the batch
- `maxlen=MAX_QUEUE` bounds memory

New messages arriving between poll and ack get included in the next poll
serving (since they're in `message_queue`), then moved to `pending_ack`
along with the old batch. This means they'll be served twice if the second
poll's ack also fails. Acceptable for at-least-once.

### INFO-2: Integration test coverage is good
**File:** `ic/tests/external_worker_integration.rs`

10 tests covering happy path, empty-output fallback, failed result, timeout,
cancel, connection failure, protocol error, pool reuse, correct auth, wrong
auth. The mock worker is well-designed (scripted behavior, subprotocol echo,
auth validation). Tests are deterministic and require no external deps.

Notable coverage gap: no test for the multi-endpoint failover retry loop
(acquire_excluding with 2+ endpoints). The unit tests cover acquire/
acquire_excluding in isolation, but the end-to-end failover path in
`execute_task` (wait=true, max_attempts > 1) is not exercised.

### INFO-3: `entrypoint.sh` nanocode override — correct but fragile
**File:** `lunarcode4lunarwing/entrypoint.sh`

The Python heredoc override path works correctly: reads the baked config,
overrides model/baseURL, writes to workspace. The fallback symlink path
is preserved when no overrides are set.

Potential fragility: if `python3` is not in the container image, the
override silently fails (heredoc syntax error, `python3` not found). But
the nanocode image is Python-based, so python3 is guaranteed present.

## What's Done Well

- **SecretString migration** (M7): auth_token → `Option<SecretString>` at
  every layer. `skip_serializing`, Debug auto-redacts, single exposure
  site via `expose_secret()`. Clean.
- **Constant-time auth** (M6): `hmac.compare_digest` replaces `!=`. Correct.
- **Body-size cap** (M5): 64KiB cap with 413/400 handling. Prevents OOM on
  the hand-rolled HTTP server. Correct.
- **Fail-closed adapter URL** (M3): empty default instead of `:6680`
  fallback. Prevents cross-tenant routing. Correct.
- **UTF-8 truncation fix** (H1): `floor_char_boundary` replaces unsafe byte
  slice. Regression tests are thorough (ASCII, accented, CJK, emoji,
  boundary-straddling). Correct.
- **Pebble subprotocol echo fix**: the `accept_hdr_async` callback now
  echoes `ironclaw-agent-v1`. This was a real production bug.
- **Image ID comparison** in `_ensure_tenant_image`: compares IDs not just
  names, preventing stale-image holdback. Correct.
- **v8 ports migration**: rename-only, idempotent, collision-checked (in
  the standalone script). The publish-alias design (host port → container
  8443) avoids image rebuilds. Smart.
- **Shellcheck gate**: `.shellcheckrc` + `check-mt-admin.sh`. Good
  infrastructure quality practice.
- **Fault injection scripts**: well-structured, dry-run support, safety
  prompt, threshold assertion. Good operational tooling.
